# v2ray-collector

Автоматический сборщик и тестер прокси-конфигов **VLESS** и **VMess**,
ориентированный на работу из России.

Каждые 6 часов GitHub Actions:
1. Скачивает ~15 публичных подписок (включая [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia)).
2. Оставляет только `vless://` и `vmess://` (Trojan / Shadowsocks отбрасываются).
3. Дедуплицирует и ограничивает пул до `MAX_POOL` конфигов.
4. Прогоняет двухэтапный тест:
   - **Этап 1 — TCP-чек** (быстрый, ~250 потоков): отсеивает мёртвые IP.
   - **Этап 2 — полный тест** через локальный `xray-core`: поднимает SOCKS-прокси,
     дважды замеряет скорость через YouTube CDN (`i.ytimg.com`), считает задержку
     и стабильность (стандартное отклонение скорости).
5. Сортирует по `stability_score` и берёт топ-**150**.
6. Добавляет эмодзи-флаги странам, где их не было (через `ip-api.com`).
7. Пишет **один файл** `output/proxies.txt` — готовый к импорту в клиент.

## Итоговый файл

В репозитории после каждого запуска лежит **ровно один файл**:

```
output/proxies.txt
```

Формат — обычный текст, по одной share-ссылке на строку, все строки
с эмодзи-флагом и названием страны:

```
vless://1bdbedca-...@31.129.42.216:443?...&mode=gun#2111 | 🇷🇺 Russia | VLESS
vmess://eyJhZGQiOiIxLjIuMy40Ii...@...#🇩🇪 Germany
vless://2c634977-...@78.159.245.75:9002?...&fp=firefox#AetrisVPN ┃ 🇫🇷 France
```

Строки идут **сверху вниз от самых быстрых и стабильных** — можно смело
подключаться к первой.

## Подписка по URL

После первого запуска можно добавить в клиент (v2rayNG, Hiddify, NekoBox,
Streisand, Happ и др.) ссылку на raw-файл:

```
https://raw.githubusercontent.com/<user>/<repo>/main/output/proxies.txt
```

Для клиентов, требующих base64-подписку, используйте параметр `?raw=1`
(или импорт «из файла» — просто скачайте `proxies.txt`).

## Локальный запуск

```bash
# 1. Скачать xray-core
wget https://github.com/XTLS/Xray-core/releases/latest/download/Xray-linux-64.zip
unzip Xray-linux-64.zip xray && chmod +x xray

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Запустить
XRAY_BIN=./xray python3 src/main.py
```

Результат появится в `output/proxies.txt`.

## Настройка

Всё, что чаще всего хочется подкрутить, лежит в двух файлах.

### `src/main.py`

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TOP_N` | `150` | сколько строк попадёт в `proxies.txt` |
| `MAX_POOL` | `4000` | сколько конфигов пойдёт на тест (остальные отбрасываются случайно) |
| `ALLOWED_PROTOCOLS` | `("vless://", "vmess://")` | какие протоколы оставлять |
| `RANDOM_SEED` | `42` | фиксирует выборку — список стабилен от запуска к запуску |
| `OUT_FILE` | `proxies.txt` | имя итогового файла |

### `src/sources.py`

Список URL-подписок — `SOURCES`. Дополнительные источники просто
добавляются строками. Работает и plain-text, и base64.

### `src/tester.py`

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MIN_SPEED_KBPS` | `50` | минимальная скорость, ниже — конфиг отбрасывается |
| `MAX_STDEV_RATIO` | `0.9` | максимальный разброс скорости (стабильность) |
| `MAX_WORKERS` | `100` | сколько xray-процессов параллельно |
| `TCP_TIMEOUT` | `2.0` | таймаут TCP-пречека (Этап 1) |
| `SPEED_TIMEOUT` | `8` | таймаут одного замера скорости |
| `XRAY_READY_TIMEOUT` | `3.0` | сколько ждать, пока xray откроет SOCKS-порт |
| `REPEAT_TESTS` | `2` | сколько раз повторять замер скорости |
| `GLOBAL_DEADLINE_SEC` | `1500` | жёсткий дедлайн теста (25 мин) — после него берётся то, что успели |
| `CHECK_FACEBOOK` | `False` | проверять ли обход блокировок РФ через Facebook |

### Расписание

`cron` в `.github/workflows/update.yml` — по умолчанию раз в 6 часов
(`0 */6 * * *`). Можно поставить `0 */1 * * *` (каждый час) или
`0 3 * * *` (раз в сутки в 3:00 UTC).

## Как работает отбор

1. **TCP-чек** — открыт ли порт. Отсеивает ~30–50 % мусора.
2. **Первый замер скорости** через YouTube CDN. Требуется HTTP 200 и ≥ `MIN_SPEED_KBPS`.
3. **Проверка обхода блокировок РФ** (опционально, выключена по умолчанию).
4. **Второй замер скорости** — вычисляется `stdev` двух замеров.
5. Если `stdev / avg_speed > MAX_STDEV_RATIO` — конфиг считается нестабильным.
6. Все прошедшие получают `stability_score = avg_speed / (1 + stdev)` и сортируются по нему.

## Частые проблемы

**`The operation was canceled`** — обычно это параллельный запуск
(`concurrency`) или превышение `timeout-minutes`. Решения:
- уменьшить `MAX_POOL` до 4000;
- ускорить тест (`MAX_WORKERS = 150`, `SPEED_TIMEOUT = 5`);
- поднять `timeout-minutes` до 90.

**Пустой `proxies.txt`** — значит все фильтры отсеяли всё. Смотрите в логе
блок `=== Причины отбраковки на этапе 2 ===`:
- много `test1:http_000` — конфиги не проходят VLESS/VMess-хендшейк, обычное дело;
- много `test1:too_slow` — снизьте `MIN_SPEED_KBPS`;
- много `xray_not_ready` — часть ссылок битые, надо расширить источники.

**Мало рабочих конфигов** — добавьте источников в `SOURCES`, увеличьте
`MAX_POOL`, снизьте `MIN_SPEED_KBPS` до 50–100.

**`! 404 Not Found` для источника** — репозиторий переименован или удалён,
просто уберите/замените URL в `SOURCES`. Скрипт продолжит с остальными.
